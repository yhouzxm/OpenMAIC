# P6 PBL 小组协作、共同提交与教师评价

2026-10-24，沿原 P1–P7 实施。交付范围是教学班内的标准知识项目协作：教师采用／编写原生项目、发布、分组，学生共同编辑、全员确认、共同提交，教师公开评价及更正，成员回看固定成果和历史。不是把个人原生聊天会话直接改成共享会话。

## 原生复用与新增差额

复用 `@openmaic/dsl` 的 PBLProject／Milestone／Microtask 合同和 `isPBLProject`、原生 `stripToDesignTemplate`、generation 的 `findMicrotask`。可直接采用标准原生 PBL v2 JSON；任务说明、交付标准、提示、参考文档及里程碑按原合同呈现。学生提交、Agent聊天、运行完成、内部评价与系统提示不作为项目设计或小组权威事实导入。原生 planner／Instructor／evaluator 和运行器均未复制或改写。

原生 `PBLRenderer` 使用个人 StageStore 和个人运行／Agent接口，不能直接赋予教学班小组授权；因此新页面只补课程内多人协作这一差额。当前是文本共同成果和共同反思，按任务填写。项目限1–8个里程碑、最多32个任务；每项成果最多2000字、反思3000字，共同成果规范化UTF8总量限48000字节。自主Agent、情景角色扮演、原生完整Runtime、多人附件编辑及自动正式AI评分不因本包而启用；已有个人附件提交及课程Tutor继续有效。

## 可以使用的闭环

- 教师从课程“PBL 小组项目”创建项目，或在“复用原生PBL v2项目”采用JSON。草稿保存与发布分开；每组固定创建时的发布版本，后续编辑／发布不重写已有小组。可以关闭／重新开放；固定版本的截止与重交规则继续有效。
- 使用现有受限教学班名册搜索／分页选人，新建每组1–10人，同一项目每人最多加入一个当前组；可清空旧组来完成整组转移，空组及历史不删除。改组需说明共享草稿交接原因；会提升名单及成果版本，使旧确认失效。退班、全局启停或学生角色撤销会阻止新写入，恢复入班后须教师显式重新交接小组。
- 组员逐任务共同编辑，保存后其他组员刷新可见。竞争保存用预期版本判冲突，保留本地未提交文字；页面保护未保存编辑和结果未确认的请求，并支持重试同一命令。组内自动刷新在编辑／操作期间暂停。
- 成员必须明确确认**同一已保存成果和同一名单版本**。任何编辑或改组后需全员重新确认；任一当前组员可提交。正式提交固定原生项目版本、成果、当时成员／Enrollment和确认时间。幂等重试只形成一次提交，重交保留旧成果及旧评价。
- 教师查看确切共同提交，显式发布0–100分与公开说明；更正必须填写公开原因，历史版本不覆盖。评价仅对该次提交成员及当前任教教师可见。新加入成员不能读取入组前未参与的正式提交；移出组成员仍可在当前课程授权有效时回看本人参加过的提交，不能再读写当前草稿。
- 教师全局／课程PBL、学生全局PBL和旧实例四类入口随本包一次接入，复用原Workspace课程选择；旧Native实例只提供明确解释与课程导航，不自动映射小组或导入旧历史。项目、小组、协作修订、共同提交和评价历史有界分页。关闭、截止及不允许重交时保留只读历史。课程上下文、直接链接和同页片段切换均可回到对应项目／小组／提交。退出会话清除页面中的私有内容。

这是小组项目评价，不自动为每名组员创建个人Attempt、活动成绩或课程总评，也不把全组分数当作每人的能力画像。

## 授权、事务和安装

新增独立 `zhiban_pbl/0001_pbl.sql`，未修改已有已应用migrations。引用原Identity／Academic的租户、任教关系与Enrollment，复用现有Academic事务及角色到期提交屏障。仅本机owned PG16验证和默认持久化实例追加安装，未触及55432／55433或生产。

冻结Bridge单次至多两名相关成员的限制保持。新增 `zhiban_pbl.lock_participants` 只对Bridge角色开放，当前租户内最多21个去重成员（旧名单10＋新名单10＋教师），按用户／成员顺序预锁，返回void，不签发授权、不修改身份、不读取凭据。随后在**同一guard事务**中逐批调用原Bridge身份校验，每批仍最多两名相关成员、每次都绑定真实会话Actor；核对同一租户／Actor授权版本，保留全部锁至业务提交。再逐名锁定当前学生角色和准确Enrollment，提交前核对角色到期。新成员未进入预先锁定的集合时失败关闭，不借用教师会话代学生确认。

新schema的业务表全部FORCE RLS；发布版本、协作修订、正式提交、评价及审计不可由runtime更新／删除，只有列级草稿／状态权限。独立fresh owned PG16构建expected catalog／ACL参考，loader核对迁移hash、ledger、helper／角色ACL与catalog；web启动不自己生成期望profile。演示发行和生产签收分开，证据统一LOCAL。

## 本地使用与证据

默认入口为 `https://127.0.0.1:3461/zhiban`，原有三角色账号仍从 `pnpm trial:zhiban:info` 的私有文件读取。进入“课堂与实验演示”课程 → “PBL 小组项目”。新增“小组协作演示：节能教室”及陈同学演示组，未预填／提交成果。默认演示沿用现有一个学生账号；真实四名学生协作在独立专项中验证，不把单人演示称为多人验收。

最终运行、直达地址、来源绑定、数据保持和新备份以 [`evidence/pbl/closeout.json`](evidence/pbl/closeout.json)、[`default-entry.json`](evidence/pbl/default-entry.json) 为准。默认启动继续恢复同一批账号、课程和历史，`pnpm trial:zhiban:stop` 成功保存快照后才清理临时root。P7归档仍保留其原source范围，本包不重打P7。

`pnpm verify:zhiban:pbl` 仅在独立owned cluster和HTTPS3468验证本包，保留默认3461。专项使用相同PG16端口号但不同私有Unix socket／数据目录，TCP均关闭，不连接默认集群。

专项证据见 [`zhiban-pbl-local.json`](evidence/zhiban-pbl-local.json)、[`zhiban-pbl-journey-local.json`](evidence/zhiban-pbl-journey-local.json)。覆盖四人分组、双浏览器协作、全员确认、正式提交与教师公开评价／更正，以及竞争保存／改组与提交、重放去重、后段SQL失败回滚、退班恢复、真实Identity角色撤销等待在途提交、跨组／租户／角色／CSRF、helper和不可变表ACL漂移、固定版本／截止／关闭／重交与历史隔离。类型、输入边界及定向lint范围在closeout列明，不宣称全仓或CI签收；早期失败记录与修正后结果并存。
