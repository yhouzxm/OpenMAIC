# 原 P3 校内证书、跨班学分与受限自动正式 AI 评分

本包是用户已授权的原 P3 差额，复用原课程／任教／Enrollment、文本与原生 Quiz、固定发布总评、人工正式发布／更正。本包已完成 LOCAL 验收及默认3461交付，最终状态与精确源码边界见 [closeout](evidence/attainment/closeout.json)。

## 可见流程与约束

- 教师课程内“AI 正式评分”：对文本作答、含简答的正式测验显式启用固定活动版本、rubric、满分、实际部署模型；学生提交在同一事务留下待办，服务自动处理。仅第一次正式评分；已有人工草稿／发布成绩不被覆盖。客观题复用原生不可变判分，模型只评简答。
- 学生作答页显示已启用的模型和固定规则；课程“AI 正式评分”显示本人服务成绩／历史和申诉。教师仍从原成绩页更正并公开原因，申诉只能解释或关联实际更正后的最新发布，不能直接改分。
- 教师课程内“校内证书”：设置名称、达标线与开关，选择名册学生，核对当前正式总评后签发。学生本人有跨课程历史入口、打印／保存 PDF 及 JSON 成果记录；撤销保留原因与历史。它是校内教学记录，不是外部职业资格、公开证书查询或数字签章服务。
- 管理员工作台“校内证书与跨班学分”：受限课程／教学班／名册选择器，配置来源课程到目标课程的等价规则、0.1–30 学分和最低总评，明确认定／撤销。按学生与目标课程去重，另一来源班不能重复累计；不自动更改目标班 Enrollment、总评或先修资格。
- 证书／学分固定签发时规则、姓名／课程／教学班、发布总评与来源摘要。后来成绩、重交、权重或名册变化只标记“依据已变化，需复核”，不会悄悄改写历史或自动重新签发。

## 服务身份与并发边界

新增独立 `zhiban_autograde_worker` 登录，无角色继承、成员关系、原始业务表权限或 Identity DML；仅能执行封闭的 prepare／apply／fail／pending／reject_request。凭据由本机私有 Unix socket 的 owned PG16 环境交付，不在网页或聊天暴露；生产凭据／多机运维未签收。

教师授权策略固定真实 grant ID、成员授权版本、活动发布版本和实际 provider／model。待办在原提交事务的触发器里保存，固定当时的 policy；教师会话不交给服务。服务准备与落库分别校验当前身份、有效授权、任教和选课、当前政策／活动、最新 Attempt／提交及既有成绩；模型运行期间不持数据库锁。私有随机 job token 只留进程内，数据库保存摘要；模型 90 秒、任务 120 秒上限，最多两个在途任务，失败关闭不隐式反复调用模型。

冻结 Identity 的 owner SELECT 策略不能对成员／授权行加锁。本包不改其策略或原 helper，而在短事务中依次锁 tenant、users，再对 memberships、role_grants 取得 SHARE 表锁，复用现有受限 SELECT。它阻止当前授权在提交前变化，代价是该短事务会阻塞其他租户的 Identity 写入；这是保守的 LOCAL 首包方案，不宣称生产吞吐已验。模型推理期间无此表锁。

落库复用原成绩与发布表，新增 nullable 服务关联列及“人类／服务二选一”约束。服务发布的 `published_by` 为 NULL，并有唯一 job 和 SERVICE 审计；触发器拒绝普通业务连接伪造服务归属／审计。人工更正清除当前成绩头的服务标识，原服务发布仍不可变。成绩、发布、Quiz 明细、服务终态和审计同事务；审计失败全部回滚。

持久待办支持重启后接续 PENDING；超时 RUNNING 关闭 FAILED，教师可显式重排。当前宿主只轮询本机注册租户；未验全局租户发现、分布式队列与生产 HA。教师取消会阻止迟到结果发布，provider 在途请求仍受 90 秒上限约束。
