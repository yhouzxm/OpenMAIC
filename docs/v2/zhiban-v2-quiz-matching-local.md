## 已确认并实现

每题2–10个左项、2–10个右项；每个左项配置一个正确右项和独立正分值（最多两位小数），右项可重复使用。逐左项完全匹配得该项全分，未答／错配零分，整数分百分位相加；题目总分必须等于左项分值之和，单卷仍遵守100题／1000分及原容量上限。

教师编辑页可新建匹配题、编辑题干、左右项、每项分值／标准配对和解析，增删左右项及整题。删除右项会清空引用它的标准配对，须重新选择后发布。右项使用固定ID，显示文字可编辑，发布时禁止空白或首尾去空白后重名的右项；缺标准配对可存草稿但不能发布。题目／整卷复制沿原深复制与独立新题ID流程，配对选项ID限定在题目内，不作为跨题或跨班权威标识。

学生为每个左项选择右项，可重复选择；沿原草稿保存、刷新续作、未保存离开保护、提交确认和历史回看。缺任一配对的题目会计入未答。客户端不作正式判分。教师沿原确认分项、显式发布及更正成绩；覆盖客观得分须提供该题公开原因及成绩更正理由，不回写旧答案键和自动判分。

## 数据与安全边界

Quiz JSON 增加 `type: matching` 与 `match.left[{label,points,correct}]`、`match.right[{id,label}]`。提交为 questionId 对应的定长右项ID数组，顺序对应左项；不对数组排序或去重。拒绝未知题号、错长度、非字符串、未知右项ID、用显示文字冒充ID及额外score／权限字段；标准配对只能引用本题现有右项。

公开投影仅返回题干、总分、左项文字／分值、右项ID／文字，不返回 correct、解析或评分指引。学生提交后仍不提前获得答案键；正式练习反馈与封卷后回看沿原开放规则。教师评分从服务端固定版本和已保存答案取证，不信任学生分数或请求中的配对键。

含匹配题整卷使用独立本地算法 `zhiban-quiz-match-1`；没有匹配题的填空卷仍为 `zhiban-quiz-fill-1`，纯原生卷仍为 `zhiban-quiz-1`。混合卷中原生和填空题继续调用各自已有判分逻辑。新算法、quiz hash、answers hash 与结果随原不可变快照和提交保存；已有 Attempt 按其固定版本的左右项／ID／标准配对／分值判分，不随源草稿修改、新版配对或右项显示顺序变化而回算。

发布数据中的 source_pin 保留原生基础能力 pin；它不代表上游已有匹配题实现。本地匹配算法与宿主来源另由本包算法标识及 source hash 绑定。

新增 `0004_matching.sql` 只扩展原两处算法 CHECK 的允许值，不修改任何已应用 migration、RLS、ACL、角色或不可变屏障。仅在 fresh owned disposable PG16 中安装；不访问55432／55433或生产。M3 setup／receipt loader 增加新迁移 hash 与精确四版 ledger 绑定；旧环境拒绝作为本版本启动，没有静默升级／重签旧安装。本轮实际验收用统一 fresh installer，未另跑独立M3完整安装旅程。
