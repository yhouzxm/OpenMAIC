# P3 简答 AI 评分建议、教师决定与原成绩发布（LOCAL）

2026-10-23。复用 OpenMAIC 的服务端 `resolveModel(stage=quiz-grade)` 和 `callLLM`，在原教师测验评分页接入完整闭环：生成简答建议→逐题检查建议分数／评语→教师采用或拒绝→原评分草稿→单独发布→学生正式成绩回看。建议按一次提交中的全部简答题成组采用或拒绝，不修改客观题算法。

## 明确规则与产品范围

- 仅当前任教教师可为本教学班、同一 Attempt 的最新提交、未发布正式成绩的 ASSESSED 测验生成和采用建议。已有发布成绩的更正继续人工走原公开更正流程；练习、客观题自动重评不包含。
- 模型只接收简答题题干、满分、评分指引及该提交答案，不传学生身份／全班名册或其他作答。评分指引复用原 `commentPrompt`；模型内容是待教师审阅的建议，不是可信判分事实。
- 服务端从固定正式版本取题目与不可变提交答案，记录 canonical SHA256、版本、提交 ID、当前 grade revision 和服务端模型配置路由。不接受客户端题目、答案、分数、模型或来源 hash。模型路由字段标识解析的配置；原生供应商 fallback 仍遵循部署配置，不把它冒充独立模型版本证明。
- 严格校验每道简答恰有一项、有效数字、0到该题满分、最多两位小数、非空有界评语；拒绝缺项、重复项、外来 ID、越界及无效 JSON。不复用原 `/api/quiz-grade` 的解析失败半分回退，也不截断／钳制非法分数。
- 教师采用仅以原 SAVE_QUIZ_GRADE 写评分草稿，客观分仍由原服务计算；原有分项保存、单独发布与更正不变。拒绝只记录决定，保留原评分。已处理的相同决定可重放，相反决定冲突。
- 评分页显示建议分数、说明和待审／已采用／已拒绝状态；未保存评分输入时不生成或处理建议，避免刷新覆盖输入。旧建议若来源已变化返回冲突，可重新生成或继续人工评分，不覆盖新评分。
- 学生响应不含建议、模型、教师决定或待审来源；发布后只读原正式成绩与允许公开的信息。

## 授权与并发

命令复用原 assessment HTTPS、CSRF、当前 Identity 和 AcademicStore。生成分三段：短事务读取可信快照→事务外调用原生模型→新事务重新检查当前授权、最新提交和 grade revision 后写建议。外部模型等待不持有 Identity／业务锁；撤权、重交、评分或发布变化使入库／采用拒绝。重复等待同一任务的请求也必须在完成后重新核验自身会话。

读取及写入按现有 progress barrier→当前教学班与任教关系→活动→Attempt 锁顺序执行。采用、原评分草稿、命令和教师决定同一事务提交；插入失败全部回滚。稳定建议 ID 和决定 ID、教学班 barrier 保证多会话决定写入一次；不同决定互斥，不覆盖。进程内最多4个模型任务，同 key 合并等待；多进程可重复调用外部模型，但数据库只承认一份建议，不承诺外部计费 exactly-once。

没有新增／修改 migrations、helper 或 ACL：建议来源与不可变决定使用既有按 tenant 隔离的 Academic commands/audit_events，分别为 `QUIZ_AI_SUGGESTION` 与 `QUIZ_AI_DECISION`；教师读投影只返回最近10条，学生投影不加载。正式分仍由既有 Assessment 表及审计承担。新增 service 仅接本地统一 host；其他 composition 未提供服务时明确 UNAVAILABLE，不自动获得权限。
